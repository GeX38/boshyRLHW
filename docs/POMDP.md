# I Wanna Be The Boshy: туториал как POMDP

## Постановка задачи

Рассматривается туториал оригинальной игры I Wanna Be The Boshy.
Цель агента — пройти его и перейти в следующую комнату.
По нумерации LiveSplit туториал имеет идентификатор `36`, выход ведёт в `3`.
Остальная кампания в задачу не входит; обучение агента для этого ДЗ не требуется.
Среда Gymnasium управляет настоящей игрой клавишами и читает данные из памяти
по исследованиям открытых инструментов спидранеров: [SOURCES.md](SOURCES.md).
Игра запускается напрямую в Windows; управление и чтение памяти используют Windows API.

## Формальная модель

Задачу описываем как P=(S,A,T,R,Omega,O,mu,gamma).

| Элемент | Определение |
| --- | --- |
| S | Полное скрытое состояние игры и удерживаемых кнопок. |
| A | Комбинации кнопок: влево, вправо, прыжок, выстрел, загрузка. |
| T| Динамика оригинальной игры за интервал взаимодействия. |
| R | Награда за шаг, смерть и выход из туториала. |
| Omega | Наблюдения (x,y,room,alive). |
| O | Чтение доступных полей памяти и преобразование в наблюдение. |
| mu | Начальное распределение при загрузке текущего checkpoint. |
| gamma | Дисконтирование будущих наград; например, 0.99 при обучении. |

Полное состояние включает координаты и скорость персонажа, направление взгляда,
число доступных прыжков, комнату, жизнь, checkpoint, состояния платформ,
опасностей, сфер и снарядов, их таймеры и фазы движения, состояние RNG при его
использовании. Удерживаемые кнопки и обработанные нажатия тоже важны для динамики.
Функцию `T` реализует сама игра; её формулу и скрытые поля среда не восстанавливает.

При одинаковых `[x, y, room, alive]` персонаж может подниматься
или падать, иметь второй прыжок или уже потратить его. Поэтому одинаковое
наблюдение и одинаковое действие могут приводить к разным следующим наблюдениям.
Доступный вектор не является состоянием MDP: задача **частично наблюдаема**.
Политика может учитывать историю: `pi(a_t | o_0, ..., o_t; a_0, ..., a_(t-1))`.
Полное состояние игры можно моделировать как MDP, но агент его не получает.

## Наблюдения и действия Gymnasium

`observation_space` — `Box(shape=(4,), dtype=np.float32)`:

```text
[x, y, room, alive]
```

`x`, `y` — координаты в системе игры; `room` — категория, записанная числом.
`alive=1` означает, что координаты персонажа доступны и детектор не видит смерти.
Если координаты недоступны, вместо них записываются нули и `alive=0`.
После выхода из туториала координаты не читаются: `alive=0` в этом случае
не означает смерть. Для завершения используются комната и отдельный детектор смерти.

`action_space = MultiBinary(5)` задаёт 32 сочетания кнопок:

| Бит | Клавиша | Действие |
| --- | --- | --- |
| `left` | ← | Движение влево. |
| `right` | → | Движение вправо. |
| `jump` | Z | Прыжок, включая второй прыжок в воздухе. |
| `shoot` | X | Выстрел; попадание в checkpoint сохраняет позицию. |
| `reload` | R | Загрузка текущего checkpoint. |

Ноль отпускает кнопку, единица удерживает её; все пять бит применяются одновременно.
Повтор `jump=1` продолжает удержание. Для второго нажатия нужно `1 → 0 → 1`.
Сферы пополняют прыжки по правилам игры. Сочетания X+Z около checkpoint
(savejump), R+Z и одновременные стрелки доступны обычными комбинациями битов.
Физику прыжков, столкновения, стрельбу, сохранения и телепорты выполняет игра;
дополнительных макродействий среда не добавляет.
Меню и настройки подготавливаются вручную. Курсор в игре сам подкрадывается
к персонажу и убивает при контакте. В этой задаче его положение фиксируется
вне игрового поля: перед каждым действием среда уводит мышь за окно.
Используется оконный режим; мышь не входит в действия агента.

## Шаг, награда и конец эпизода

`step(a)` задаёт кнопки, ждёт номинально `dt = 0.05` с и читает память.
Игра продолжает работать во время чтения и между вызовами Python, поэтому шаг
не равен фиксированному числу игровых кадров. Реальные задержки взаимодействия
входят в приближение `T`; это модель игры с опросом в реальном времени.

```text
r_t = -0.001 - 10 * death_t + 100 * success_t
```

`death_t` и `success_t` равны 1, если на шаге произошла смерть или успешный
выход соответственно, и 0 в остальных случаях.

Успех — переход из туториала `36` в целевую комнату `3` без признака смерти.
За движение вправо награды нет: оно не всегда означает прогресс.
Телепорт после падения без смерти также не штрафуется отдельно.
Агент максимизирует ожидаемую сумму наград с дисконтированием:

```text
E_pi[r_0 + gamma * r_1 + gamma^2 * r_2 + ... + gamma^(N-1) * r_(N-1)]
```

Здесь `E_pi` — математическое ожидание при политике `pi`, а `N` — число шагов
до конца эпизода.

- Смерть или успешный выход: `terminated=True`.
- Лимит 1000 шагов или переход в постороннюю комнату: `truncated=True`.
- Ошибка чтения памяти вызывает исключение, а не игровую смерть.

При завершении управляемые кнопки отпускаются. Опрос фиксирует состояние
в моменты чтения; очень короткое событие между ними может остаться незамеченным.
`step()` возвращает `(observation, reward, terminated, truncated, info)`.
Нулевой кадр при инициализации сцены кратко пропускается: отсутствие игрока
в этот момент ещё не означает смерть.

## Начало эпизода и сохранения

`reset()` загружает текущий checkpoint кнопкой R. После обработки загрузки
среда ждёт ещё два игровых такта: первый такт может показывать временную
позицию персонажа до применения checkpoint. Возвращаются `(observation, info)`.
Для вручную подготовленной точки можно вызвать
`reset(options={"keep_position": True})`: эпизод начинается с текущей позиции без R.

Выстрел в checkpoint может менять сохранение, поэтому начальное распределение
`mu` зависит от текущего checkpoint `c`, который входит в скрытое состояние.
Сброс не восстанавливает неизменный savestate: следующие эпизоды могут начинаться
с более поздней точки туториала. Для сравнения агентов нужно заранее подготовить
одинаковое сохранение. `reset(seed=...)` не устанавливает RNG оригинальной игры.
