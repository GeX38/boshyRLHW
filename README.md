# Boshy RL — домашняя работа 1

**I Wanna Be The Boshy** описана как POMDP и подключена к Gymnasium.
Задача — пройти туториал: из комнаты **36** выйти в комнату **3**.
[Описание POMDP](docs/POMDP.md) · [Источники адресов памяти](docs/SOURCES.md)

Наблюдение — вектор `np.float32 [x, y, room, alive]` из памяти игры.
Собственный читатель использует опубликованные исследования LiveSplit и boshyst.
Скорость, запас прыжков и состояние опасностей скрыты, поэтому это POMDP.
Обучение агента в эту работу не входит; `main.py` только демонстрирует вызовы среды.

- Действие: `MultiBinary(5)` — `[left, right, jump, shoot, reload]`.
- Управление: стрелки, Z, X, R; каждый бит задаёт удержание клавиши.
- Второй прыжок требует отпустить и снова нажать Z; обе стрелки допустимы вместе.
- Сохранение активируется выстрелом X в checkpoint, R загружает текущий checkpoint.
- Награда: −0.001 за шаг, дополнительно −10 за смерть или +100 за выход.
- Смерть и цель завершают эпизод; лимит 1000 шагов или другая комната прерывают его.

## Установка

Нужны Windows и Python 3.10 или новее.
Помести 32-битную игру в `assets/game/I Wanna Be The Boshy.exe`.
Смещения памяти рассчитаны на локальную сборку игры.
При переносе проекта заново создай `.venv`: окружение Python с другой системы
копировать не нужно. Команды ниже выполняются в PowerShell из папки проекта.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Запуск

```powershell
.\.venv\Scripts\python.exe main.py
```

Скрипт запускает игру. Вручную открой туториал и подготовь сохранение.
Вернись в терминал, нажми Enter и за 5 секунд переключись в окно игры.
Используй английскую раскладку. При ручной подготовке держи курсор вне игры:
в Boshy он сам подкрадывается к персонажу и убивает его.
Перед каждым действием среда автоматически переносит курсор за окно.
Используется оконный режим игры; окно должно оставаться активным.
По умолчанию выполняется 20 действий с выводом результатов в терминал.
Можно задать `--steps 20` и добавить `--random` для случайных действий.

Среда — [BoshyEnv](boshy_env/env.py), параметры — в [config.py](boshy_env/config.py).
`reset()` загружает текущий checkpoint. После выхода вернись в туториал вручную.
Игра идёт между вызовами Python, `seed` не задаёт её RNG;
быстрая смерть между опросами может остаться незамеченной.

## Как это работает

1. `main.py` запускает EXE оригинальной игры напрямую. Туториал открывается вручную.
2. `env.step([left, right, jump, shoot, reload])` передаёт пять бит в управление.
   Windows API `SendInput` нажимает или отпускает соответствующие клавиши;
   среда ждёт около 0.05 с.
3. Игра сама обрабатывает движение, прыжки, выстрелы и столкновения.
4. `memory.py` через `ReadProcessMemory` читает память процесса: комнату, координаты,
   признак смерти и счётчик игровых кадров. Базовый адрес EXE определяется
   через Toolhelp32. Смещения взяты из открытых LiveSplit ASL и boshyst;
   сами LiveSplit и DLL boshyst для запуска не нужны. Память игры не изменяется.
5. `env.py` формирует наблюдение `[x, y, room, alive]`, вычисляет награду
   и признаки конца эпизода. Они возвращаются вызывающему Python-коду.

`reset()` отправляет R и ждёт применения текущего сохранения.
Если точка уже подготовлена вручную, `reset(options={"keep_position": True})`
начинает эпизод с текущей позиции без нажатия R.
`render()` при запросе снимает изображение окна через Pillow в исходном размере;
для наблюдения и награды изображение не используется.

## Что проверено

В предыдущей версии через Wine на настоящей игре проверены движение,
повторное нажатие прыжка, выстрел, смерть и загрузка сохранения.
После попадания в checkpoint сохранение изменилось;
после ухода с точки `reset()` вернул персонажа в `(2697, 319)`.
Переход из туториала в World 1 также проверен на настоящей игре:
из вручную подготовленной точки `(3736, 447)` действия через `step()` привели
в комнату `3`. Итог: `reward=99.999`, `terminated=True`, `truncated=False`,
`is_success=True`. Обучение агента не запускалось.
В Windows проверены нативный запуск EXE, чтение памяти через Windows API,
загрузка текущего checkpoint кнопкой R и RGB-снимок окна. Все семь тестов
Gymnasium прошли под Windows Python 3.12. Полный переход `36 → 3`
после переноса повторно не проверялся.
